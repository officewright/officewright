# Corpus sources

Every file under `tests/corpus/` is listed here with its origin and license. Only files
whose license allows redistribution are committed; never personal, customer or
copyrighted documents. Each file is under 1 MB and the whole corpus under 50 MB.

## Documents

The documents under `word-rules/` are written by `scripts/make-rule-docs.py`, one layout
rule per document (and one document per compatibility mode or `w:compat` flag when the rule
depends on it). `scripts/check.sh` fails when a committed file differs from what the script
writes.

## Reference renders (`reference/`)

Made from PDFs exported by Microsoft Word, Excel or PowerPoint from the documents above
(`scripts/windows/make-reference.ps1`). A LibreOffice export is a secondary reference
and says so in the Application column.

The PDFs are not committed: they hold subsets of the fonts the application used,
Microsoft's among them. The maintainer keeps them; each row gives the PDF's SHA-256. For
every document `scripts/corpus-import.py` writes a folder `reference/<group>/<name>/` with
`page-001.png`, ... (every page rasterized by poppler's `pdftoppm` at 110 dpi in 8-bit
grey) and `geometry.json` (page sizes, the boxes of every line and word from
`pdftotext -bbox-layout` in points from the top left of the page, the page count, and Word's
page breaks). Fonts the PDF only references without embedding them are embedded into a
temporary copy of it before rasterizing, from the maintainer's own installed font files, so
the PNG files show Word's glyphs; the Notes name each such font by version and SHA-256, never
by path. No Windows font is named Helvetica: Windows draws Helvetica and Helvetica,Bold with
Arial and Arial Bold, and so do the rasters, with a note "drawn with ArialMT as Windows
substitutes it".

Word saves each document again before it exports it, and the PDF is made from that saved
copy, which is kept under `resaved/` with the same path: its `w:lastRenderedPageBreak`
marks are Word's page breaks for that PDF. The Notes give the compatibility mode Word used,
the page count, Word's printer (Microsoft Print to PDF, or a note that another printer was
used, without its name), the fonts Word did not have and substituted, the legacy `w:compat`
settings Word dropped from the re-saved copy (those it does not apply in the document's
mode), from #297 on how many style and numbering properties Word dropped from the re-saved
copy, added to the styles, levels and lists the input had, and changed, and how many body
paragraphs it gave another style (`geometry.json` lists each one), how fields were rendered,
the PDF's SHA-256 and the poppler version. Word sometimes
writes a language tag or number format into the re-saved copy that the input did not have,
which says where Word ran. Such a copy is imported only when the maintainer accepts it
(`--allow-locale`), and its Notes then list each such change after "accepted with
--allow-locale".

From `make-reference.ps1` format 3 on, the folder also holds `formatting.json`: the
formatting Word computes for every paragraph of every story (whether its style is built in,
indents, spacing, line spacing, alignment, the list label and the first character's font),
and the body paragraphs' style ids and names taken from the re-saved copy. The note
"formatting as Word computes it" gives the number of paragraphs and says whether the file
holds the runs of formatting too: "with runs"; "without runs" when Word failed to give them,
took longer for them than for the paragraphs, or ran out of time (its `runs_note` says
which); "runs left out (size)" when they would make the file larger than 900,000 bytes,
which keeps it under 1 MB. "incomplete (time budget)" means Word ran out of time before the
last paragraph, and "body styles not matched to the re-saved copy" that the body paragraphs
of the export and of the copy did not line up, so the style ids are left out. Word folds an
empty paragraph whose mark is hidden into the paragraph after it, and the export has one entry
